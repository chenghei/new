# 优选商城 · 多端电商系统（毕业设计）

一个包含 **用户端、商家端、管理端** 三端 + 统一后端的电商系统，并接入大模型（DeepSeek）实现 AI 导购、AI 商品文案生成与 AI 评价分析。

- 用户端（`userMall`）：浏览/搜索商品、AI 购物助手、购物车与收藏、下单支付、评价与售后、收货地址
- 商家端（`merchant`）：入驻申请与店铺管理、商品管理、AI 商品助手、订单发货、售后处理、评论管理与 AI 分析、经营数据统计
- 管理端（`admin`）：用户与商家管理、店铺/商品审核、分类管理、订单与售后监管、平台数据统计、AI 调用与配置管理

## 一、技术栈

| 层次 | 技术 |
|---|---|
| 后端 | Node.js + Express 4 + Sequelize 6 + MySQL 8 + JWT + Multer |
| 前端（三端） | Vue 3 + Vite 4 + Element Plus + Pinia + Vue Router + Axios |
| 图表 | ECharts 5（商家端、管理端数据统计） |

```
   用户端 userMall :3001 ─┐                            │
   商家端 merchant :3002 ─┼──► 后端 API :5000 ──► MySQL (mall)
   管理端 admin    :3003 ─┘        │
                                   ├──► DeepSeek API（AI 能力）
                                   └──► backend/uploads（本地上传图片，经 /uploads 对外提供）
```

| 服务 | 目录 | 端口 | 说明 |
|---|---|---|---|
| 后端 API | `backend` | 5000 | 统一提供 REST 接口与静态图片服务 |
| 用户端 | `userMall` | 3001 | 消费者购物界面 |
| 商家端 | `merchant` | 3002 | 商家经营后台 |

## 四、快速开始

### 1. 环境要求
- Node.js ≥ 16（建议 18）
- MySQL ≥ 5.7（建议 8.x）

### 2. 准备数据库
新建数据库（默认名 `mall`），并在 `backend/.env` 中配置：

```ini
DB_HOST=localhost
DB_USER=root
DB_PASSWORD=你的密码
DB_NAME=mall
DB_PORT=3306

JWT_SECRET=your-super-secret-jwt-key-here
JWT_EXPIRES_IN=7d

PORT=5000
NODE_ENV=development

# AI（可选，也可在管理端「AI服务配置」中维护）
DEEPSEEK_API_KEY=sk-xxxxxxxx
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
```

> 首次启动会自动创建/同步数据表（`sequelize.sync()`）。
> 若后续新增了字段需要同步表结构，临时以 `DB_SYNC_ALTER=true` 启动一次即可（不要常开，原因见「并发与安全设计」文档）。

### 3. 启动后端
```bash
cd backend
npm install
npm run dev          # http://localhost:5000/api
```

### 4. 启动三个前端（分别开三个终端）
```bash
cd userMall && npm install && npm run dev    # http://localhost:3001
cd merchant && npm install && npm run dev    # http://localhost:3002
cd admin    && npm install && npm run dev    # http://localhost:3003
```

### 5. 初始化测试数据（可选但推荐）
```bash
cd backend
npm run seed          # 已有数据时自动跳过，不会重复写入
npm run seed:reset    # 清空业务数据后重新生成
```
会生成：8 个分类、6 个商家账号（4 通过 / 1 待审核 / 1 已拒绝）、4 个买家、24 件商品、
28 笔订单（覆盖 5 种状态）、14 条评价、7 条售后（含异常单）、收藏/购物车/浏览足迹、AI 调用记录，以及每位买家的默认收货地址。

> 种子脚本会优先使用 `backend/uploads/local-images.json` 中的本地图片；若该清单不存在则回退到远程文生图地址。

### 6. 图片本地化（可选）
项目中的演示图片（商品图、店铺 Logo/资质、首页轮播图）已全部下载到 `backend/uploads`，并通过 `/uploads/<文件名>` 本地访问，不依赖外部图床。若需要重新下载/更新：

```bash
cd backend
npm run localize-images
```
脚本会把数据库中仍是远程地址的图片下载到 `backend/uploads`、把记录改写为本地文件名，并生成 `uploads/local-images.json` 清单供种子脚本复用。

## 七、技术亮点

### 7.1 AI 能力（DeepSeek 大模型）
- **AI 个性化推荐**：把用户行为画像（浏览/收藏/购买）+ 在售候选商品交给模型挑选并生成推荐理由；无行为数据或模型不可用时自动降级为热销推荐，接口永远可用。
- **AI 导购对话**：注入行为画像与商品清单的多轮对话，按约定格式输出便于前端解析成商品卡片。
- **AI 商品文案生成**：输入名称/分类/特点，输出结构化标题 + 卖点 + 描述（JSON 模式）。
- **AI 评价分析**：情感统计 + 主题提取（正面点/负面点/关注点/常见问题/优化建议），模型不可用时降级为规则化摘要。
- **AI 运营管理**：每次调用写入调用记录（场景、入参、输出、耗时、状态、失败原因）；管理员可在后台维护 AI 配置，密钥脱敏展示。

### 7.2 并发一致性
下单扣库存、订单状态流转、售后回补库存、售后重复申请、收藏切换等场景均做了并发处理（原子 SQL / 条件更新 / 事务 + 行锁），并已用真实并发请求验证。
详见 [docs/并发与安全设计.md](docs/并发与安全设计.md)。

### 7.3 安全设计
bcrypt 密码哈希、JWT 鉴权与角色中间件、Helmet 安全响应头、全局限流、上传类型与大小限制、AI 密钥接口脱敏、ORM 参数化查询防注入。
详见 [docs/并发与安全设计.md](docs/并发与安全设计.md)。

## 九、已知限制与可改进点

- 身份证号、AI 密钥在数据库中以明文存储（接口层已脱敏），生产环境建议加密存储并使用 KMS。
- 单机部署，并发控制依赖数据库（原子 SQL / 事务行锁），未引入 Redis 分布式锁；多实例部署时需补充。
- 图片上传为本地磁盘存储，未做压缩、水印、病毒扫描，也未接入对象存储。
- AI 调用无缓存与排队机制，高并发下依赖 DeepSeek 侧限流（失败会记录为 failed 并降级）。
- 尚未编写自动化测试用例（`jest`/`supertest` 已安装但无测试文件）。
- 支付为模拟支付，未对接真实支付网关。
